# Instruções para o Codex — Bootcamp Itaú Java + IA

Este repositório pertence ao estudante e é usado para **prática real** durante o Bootcamp Itaú — Java com Inteligência Artificial da DIO.

## Fonte de mentoria da DIO

Antes de orientar atividades do bootcamp, consulte o DIO Agent oficial disponível em:

- `ferramentas/dio-agent/AGENTS.md`
- `ferramentas/dio-agent/agent/`
- `ferramentas/dio-agent/skills/`

Quando a tarefa corresponder a uma skill, leia e siga o respectivo `SKILL.md`, principalmente:

- `skills/unblock-challenge/SKILL.md` para destravar desafios;
- `skills/explain-concept/SKILL.md` para explicar conceitos;
- `skills/study-plan/SKILL.md` para plano de estudos;
- `skills/web-search/SKILL.md` para informações atuais/verificáveis.

O conteúdo em `ferramentas/dio-agent` é material externo oficial da DIO. **Não o apresente como código criado pelo estudante e não o edite para resolver atividades.**

## Como trabalhar neste repositório

O código produzido pelo estudante deve ficar em:

- `praticas/` — exercícios, experimentos e exemplos executáveis;
- `desafios/` — desafios propostos pelo bootcamp;
- `projetos/` — projetos maiores.

### Princípios

1. Priorize prática e entendimento, não conclusão automática.
2. Antes de sugerir mudanças, leia o código atual do estudante.
3. Em desafios do bootcamp, não entregue uma solução completa pronta para copiar e colar. Use diagnóstico, perguntas curtas e dicas graduais conforme a skill oficial da DIO.
4. Explique erros de compilação, lógica e conceitos de Java de forma objetiva e conectada ao código real.
5. Prefira mudanças pequenas e verificáveis.
6. Não invente requisitos do desafio. Se o enunciado não estiver no repositório ou na conversa, peça o texto ou o link correspondente.
7. Preserve autoria: material oficial da DIO fica no submodule; código do estudante fica fora dele.
8. Quando houver código novo, ajude a manter nomes, pastas e commits claros.
9. Para exercícios simples, evite abstrações desnecessárias. Primeiro faça funcionar de forma compreensível; depois refatore.
10. Ao concluir uma etapa, indique como executar/testar o código e o que foi aprendido na prática.

## Contexto técnico

A trilha é focada em Java e Inteligência Artificial. O estudante também já trabalha com Git/GitHub e está desenvolvendo experiência de back-end. Use comparações com outros conceitos apenas quando ajudarem a entender Java; não desvie o exercício para outra stack.

## Objetivo do histórico Git

O histórico deve mostrar trabalho real. Não crie commits vazios ou alterações sem propósito apenas para aumentar contribuições. Commits devem corresponder a exercícios, desafios, correções, refatorações ou documentação útil.

## Prioridade de desenvolvimento

A prioridade do estudante é **construir os projetos e desafios reais** do bootcamp; exercícios avulsos são apoio, não o objetivo principal. Sempre que solicitado a continuar a trilha:

1. Consulte primeiro o índice de `projetos/README.md` e o projeto escolhido, incluindo o enunciado original vinculado.
2. Se a tarefa for um desafio independente, consulte `desafios/README.md` e os materiais específicos disponíveis.
3. Use `praticas/exercicios-java-basico/` para estudar fundamentos ou cumprir as atividades práticas, sem deslocar o foco dos projetos.
4. Não apresente checklists planejados como código implementado. Crie código somente durante a execução efetiva do projeto, seguindo o ritmo e as decisões do estudante.
5. Preserve a distinção entre enunciados oficiais da DIO, documentação de organização e código autoral do estudante.
